DataLad

Software · since 2013 · Home page

DataLad is ongoing work funded by NSF and German BMBF, to adapt the model of open-source software (OSS) distributions to address the technical limitations of today's data-sharing and provides a versatile data management platform. It uses software for data tracking and deployment logistics specialized for large data (git-annex) built atop Git, the most capable distributed version control system (dVCS) available today. DataLad provides access to data available from various sources (e.g. lab or consortium web-sites such as humanconnectome.org; data sharing portals such as openneuro.org and crcns.org) through a single interface. It enables students and scientists to operate on data using familiar concepts, such as files and directories, while transparently managing data access and authorization with underlying hosting providers.

  • M. Hanke, M. Visconti di Oleggio Castello, K. Meyer, B. Poldrack, and Y.O. Halchenko (2018). YODA: YODA's organigram on data analysis. OHBM 2018, Singapore.
  • JOSS paper: providing a succinct overview of DataLad
  • DataLad Handbook: everything you need to know about DataLad.
  • Funding support
  • datalad-container: a DataLad extension for working with containerized computational environments. It enables version-controlled execution of containerized pipelines (Singularity, Docker, and others) with full provenance capture as DataLad run records.
  • datalad-fuse: a DataLad extension to read annexed files from their remote URLs without a full download — sparse fetching via fsspec and optional FUSE mount give immediate access to petabyte-scale datasets.
7 components
  • datalad-crawler: DataLad extension for tracking web resources as datasets
  • datalad-deprecated: Retired DataLad functionality, kept available
  • datalad-installer: Installation script for DataLad and its dependencies
  • datalad-metalad: Next generation metadata handling for DataLad
  • datalad-neuroimaging: DataLad extension for neuroimaging data
  • datalad/git-annex: Build and distribution infrastructure that packages git-annex for DataLad's platforms. Not upstream git-annex, which Joey Hess develops.
  • datasets.datalad.org: Registry of public datasets provided by the DataLad project

NeuroDebian

Software · since 2010 · Home page

NeuroDebian is a turnkey research software platform for all aspects of the neuroscientific research process. It takes the ideas of the software hosting portals such as NITRC on maximizing research transparency and methods sharing, one step further, by providing a comprehensive suite of readily usable and fully integrated software with a robust testing and deployment infrastructure. Consequently, it improves interoperability among the tools and frees researchers from the burden of tedious installation or upgrade procedures. That, in turn, positively affects their availability for actual research activities, as well as their motivation to test new analysis tools and stay connected with the latest methodological developments in the field.

  • Y.O. Halchenko & M. Hanke (2012). Open is not enough. Let's take the next step: An integrated, community-driven computing platform for neuroscience. Frontiers in Neuroinformatics, 6:22. [PDF] DOI: 10.3389/fninf.2012.00022

PyMVPA

Software · since 2009 · Home page

PyMVPA is a Python-based framework for neural decoding using multivariate pattern analysis. It affords both volume- and surface-based analyses using a wide variety of supervised and unsupervised machine learning methods, representational similarity analyses, searchlight analyses, hyperalignment of representational spaces, and model-based decoding and encoding. The software also can be used for neural data other than fMRI, including analysis of MEG and EEG data through spatio-temporo-frequency band searchlights and cross-modal EEG to fMRI trans-fusion. It also has been used for analyses on data unrelated to neuroscience, demonstrating its general utility. PyMVPA also serves as a repository for sample data sets (e.g., Haxby et al. 2001) that has found wide applicability for education, development of new algorithms, or new analyses and independent research reports.

  • M. Hanke, Y.O. Halchenko, et al. (2009). PyMVPA: A Python toolbox for multivariate pattern analysis of fMRI data. Neuroinformatics, 7, 37-53. DOI: 10.1007/s12021-008-9041-y

mechababs

Software · since 2026 · Home page

mechababs runs BIDS Apps over many studies on an HPC cluster, with BABS running the jobs. It works on a BIDS study, adding derivatives to it, and records how each one was made inside the study itself: the exact mechababs and BABS versions pinned in a lock, and every orchestration step as a DataLad run record. A superstudy groups many studies so one campaign sweeps them all, which is how mechababs feeds OpenNeuroStudies.

MyKrok

Software · since 2025 · Home page

MyKrok (Ukrainian: "мій крок" — "my step") is a CLI tool to incrementally back up fitness activities from Strava, including GPS tracks, photos, comments, and kudos. Backups are browsable offline through a built-in web frontend with interactive maps and activity statistics — applying the same git-annex / open-data philosophy of CON's archival tools to personal fitness data. con/duct

Software · since 2024 · Repository

con/duct (or just duct) is a lightweight wrapper that collects execution data for an arbitrary command. Execution data includes execution time, system information, and resource usage statistics of the command and all its child processes. duct is intended to simplify the problem of recording the resources necessary to execute a command, particularly in an HPC environment. Additionally duct includes optional helpers that interact with logs produced by duct exectutions.

con/solidation

Software · since 2023 · Home page

con/solidation is a command-line tool that produces a Markdown activity report of recent issue and pull-request events across a configured set of GitHub repositories and organizations. It is used by CON to generate regular summaries of activity across the projects it maintains and contributes to, enabling lightweight project-health monitoring without leaving the terminal.

con/tinuous

Software · since 2021 · Repository

con/tinuous is a command for downloading build logs and (for GitHub only) artifacts and release assets for a GitHub repository from GitHub Actions, Travis-CI.com, and/or Appveyor. By downloading them all, and optionally placing them under DataLad control you can establish the backup, distribution, and convenient harmonious access to all those artifacts.

DataLad-Registry

Software · since 2020 · Home page

DataLad-Registry is a service that maintains up-to-date information on an expanding collection of datasets, currently numbering over ten thousand. It automatically registers datasets from various online sources, extracts metadata, and keeps both the datasets and their metadata current. DataLad-Registry offers search functionalities, including metadata-based searches, accessible through both a web interface and a RESTful API. Registry is regularly updated with DataLad datasets discovered across multiple hosting portals and listed on our DataLad Usage Dashboard.

con/tributors

Software · since 2020 · Home page

con/tributors is a Python library and GitHub Action to automate maintenance of contributor attribution files. It updates all-contributors, Zenodo metadata (.zenodo.json), and CodeMeta (codemeta.json) files in one go, using a shared .tributors cache that maps GitHub logins to ORCID iDs and other persistent identifiers — so that contributor records stay consistent and up-to-date across all metadata files with a single command. For example, DataLad uses a dedicated GitHub Actions workflow powered by con/tributors to automatically keep its contributor files current.

con/fscacher

Software · since 2020 · Home page

con/fscacher is a Python library providing a persistent, file-content-aware memoization cache. Functions decorated with @cache.memoize_path are re-executed only when the fingerprint (timestamps + size) of their file arguments changes — making it easy to cache expensive operations on large file trees without stale results. It is used internally by the DANDI client and other CON tools.

ReproNim/containers

Software · since 2019 · Repository

ReproNim/containers is a DataLad dataset providing a ready-to-use "distribution" of containerized neuroimaging environments (Singularity images) for reproducible analysis. It collects a curated set of containers — including those used by HeuDiConv and the broader ReproNim ecosystem — and exposes them via the ///repronim/containers DataLad dataset path, making it trivial to pin and share exact software environments alongside data and workflows.

HeuDiConv / ReproIn

Software · since 2015 · Repository

HeuDiConv is a flexible DICOM converter for organizing brain imaging data into structured directory layouts. As a part of the larger, NIH supported ReproNim effort, we are developing a HeuDiConv-based ReproIn solution for turnkey automatic conversion of all collected MR data to a collection of the BIDS DataLad datasets. It includes a flexible BIDS-like specification how to name scanning sequences in the scanner, and a HeuDiConv reproin.py heuristic to automate layout and conversion of the datasets. This solution is deployed at DBIC (Dartmouth Brain Imaging Center), it already facilitates reproducible research, data sharing, and uploads to central archives such as NDA.

  • Halchenko et al., (2024). HeuDiConv — flexible DICOM conversion into structured directory layouts. Journal of Open Source Software, 9(99), 5839 DOI: 10.21105/joss.05839.
  • M. Visconti di Oleggio Castello, James E. Dobson, Terry Sackett, Chandana Kodiweera, J.V. Haxby, M. Goncalves, S. Ghosh, Y.O. Halchenko ReproIn: automatic generation of shareable, version-controlled BIDS datasets from MR scanners, OHBM 2018, Singapore.

DueCredit

Software · since 2015 · Repository

DueCredit provides solution for the problem of inadequate citation and referencing of scientific software and methods. It provides a simple framework (at the moment for Python only) to embed publication or other references in the original code so they are automatically collected and reported to the user at the necessary level of reference detail, i.e. only references for actually used functionality will be presented back if software provides multiple citeable implementations.

As a side-effect, we hope that DueCredit also will reduce demand in "prima-ballerina" projects, will encourage contributions to existing open-source codebases, and as a result would solidify scientific software ecosystem.

  • Y.O. Halchenko and M. Visconti di Oleggio Castello (2016). DueCredit - automagically collect citations for software, methods, and data you use. OHBM 2016, Geneva, Switzerland

DANDI

Archives · since 2019 · Home page

Distributed Archives for Neurophysiology Data Integration (DANDI) is a platform for publishing, sharing, and processing neurophysiology data funded by the BRAIN Initiative. The platform is now available for data upload and distribution, and provides supplementary client tools to assist with introspection and organization of data following NWB standard.

  • NIH (#1R24MH117295-01A1). PIs: S. Ghosh and Y.O. Halchenko

The first campaign applies the AIND ephys pipeline to electrophysiology dandisets, with orchestration code and a public job queue hosted in the dandi-compute GitHub organization.

STAMPED Principles

Standards · since 2026 · Home page

STAMPED is a set of seven principles, Self-containment, Tracking, Actionability, Modularity, Portability, Ephemerality, and Distributability, for building research objects that others can trust, rerun, and build upon. Each principle is a spectrum from a practical minimum to an aspirational ideal, so adoption can be incremental and start from existing practice. STAMPED grew out of YODA and comes with an interactive checklist and worked examples.

  • Austin Macdonald, Cody C. Baker, Isaac To, John A. Lee, Yaroslav O. Halchenko. STAMPED principles for reproducible research objects (preprint). DOI: 10.31222/osf.io/f3h82_v1
  • 🎬 Talk by Cody C. Baker introducing STAMPED — archived on CON/tube.
  • 🎬 YODA: Structure your studies, observable and reproducible they become — webinar recording archived on CON/tube.

DICOM

Standards · Home page

The standard for medical imaging data and its exchange, and the format every MRI scanner writes. Everything downstream -- BIDS layouts, HeuDiConv, ReproIn -- starts from what the scanner put in the DICOM header.

Within it: DICOM WG-16, DICOM WG-32

DICOM WG-16

Standards · Home page

The DICOM working group responsible for MR. Where the conventions that make a scanner's output machine-readable are argued out, which is upstream of every BIDS conversion CON does.

DICOM WG-32

Standards · Home page

The DICOM working group on imaging compression. CON's interest is empirical: what lossy compression actually costs downstream analyses, which is what the compression-comparisons studies measure.

Components:

  • compression-comparisons: Reproducing and extending the DICOM WG-32 compression work: what lossy compression costs, measured rather than assumed.
  • compression-comparisons-t261-study: Reproduction of the compression-effects-on-spike-sorting paper, extended to the T.261 codec.

NIDM

Standards · Home page

A family of specifications for describing neuroimaging experiments, their data and their provenance, built on W3C PROV. NIDM-PROV is its provenance layer, and the ancestor of the provenance work now carried into BIDS as BEP028.

Open Brain Consent

Initiatives · since 2015 · Home page

Open Brain Consent initiative aims to facilitate neuroimaging data sharing by providing an "out of the box" solution addressing aforementioned human subjects concerns and consisting of

  • widely acceptable consent form allowing deposition of anonymized data to public data archives
  • collection of tools/pipelines to help anonymization of neuroimaging data making it ready for sharing

Initiated and managed by CON, OBC is now an international effort with materials for GDPR compliance and multiple internationalization efforts to make sure materials are available in all applicable languages. Contribute if you see your language is missing!

ReproNim TR&D3

Initiatives · Home page

The technology research and development project within ReproNim that YOH leads at Dartmouth. In practice it is the tooling that makes a study reproducible end to end: capturing what the scanner and the stimulus computer actually did, converting it into standard layouts without a human in the loop, and re-running the analysis in a recorded environment.

Components:

  • ReproEvents: An event relay device: a single-board microcontroller running micropython that sits between the input peripherals a participant uses and the event recording system, so button presses are timestamped by hardware rather than by whatever the stimulus computer was doing.
  • ReproIn: A convention and a setup for naming sequences at the scanner so that conversion to a shareable, version-controlled BIDS dataset needs no human in the loop. Runs on HeuDiConv; deployed at DBIC.
  • ReproMan: Tool for creating and managing reproducible computation environments and executing analyses in them.
  • ReproStim: Automated capture of the audio-visual stimuli actually presented during an experiment, into BIDS datasets -- so what the participant saw and heard is recorded rather than inferred from the script that was supposed to show it.
  • con/duct: Lightweight wrapper that records execution time, CPU and memory usage of a command, for resource-aware reproducible runs.
